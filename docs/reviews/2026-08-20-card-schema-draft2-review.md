## 0. Verdict in one paragraph

Draft-2 is implementable in its arithmetic — the implementer's hasher reproduces every must-equal and must-differ corpus pair, the chain verifies, the hook-append and the shape checks work — and it is **not buildable as written on four points that are not choices**, each found independently by two lenses: (1) the head layout it mandates is impossible in TOML (`history` cannot be the last key once any `[[…]]` table exists; the doc's own example parses with `history` nested inside a scenario); (2) the factory is both forbidden from and required to write card files (the `closed` entry "written by ingest", the import that must create 235 files); (3) the projected-status table misclassifies every pre-ingest human closure as drift and every born-closed migrated card as `unratified`; (4) the chain's central promise — that a hand-written entry cannot verify — is false, because the chain has no secret: anyone can recompute it. Around the gate itself the attacker found three holes that undercut "enforcement by design": the signature binds only the build hash, so it replays across hold-clears, reopens, clones and rollbacks; the file that names the ratifier keys is governed by itself; and the in-session agent is operationally the owner's session, so a cached software key makes gate (b) equal to gate (a). The maintainer's board render answers the readability question plainly — **no**: the 120-character cap truncates every sartor line to its title, the derived fallback is "filed during `<branch>`" for 57 of 73 live items, WIP reads zero, epics lose their children, and the line has no id. None of the fixes changes an owner-ratified shape; they change what "made true, not claimed" is actually true of. Twelve calls are the owner's (section 1); the rest is a pinning pass (section 2).

## 2. Fill worklist for draft-3 (mechanics; no ruling needed)

## 3. Rejected / declared

- **L6** `scope_mark = "owner-ratified"` over a promoted legacy body is the owner's signature on agent prose — accepted, named. (M §4)
