# Adversarial review — card schema shape (2026-08-16)

> **Owner ruling 2026-08-17: "confirmed on all"** — S1–S12 [owner-ratified]; F1–F23 proceed as fill mechanics; R1 stands rejected; the owner also directed "let's keep reviewing" (loop-until-dry). Applied to `03-card-schema.md` as draft-1.

## 0. Verdict in one paragraph

The shape holds where it was ratified (TOML head; one `state.json`; state split; ids; kinds on two axes; kind-per-scenario dialect; memory tier scoped to the tier). All three refuters independently converged on the same three real defects: (1) **the fingerprint's membership is wrong** — putting `closure` / `reopen_reason` inside the gated hash makes closure-binding self-referential and turns record-keeping edits into reopens, and the hash input list is incomplete/underspecified for two hashers to agree; (2) **"the payload carries exactly the gated set / invisible to the line" is currently a claim, not a mechanism** — the executor works in a checkout that contains the card file and `state.json`; (3) **the brownfield's owner-intent states have no home** — sartor's board is 58/98 items in `blocked` / `deferred` / `watching`, which the shape collapses to `draft`, and 137 already-closed items cannot migrate without being `disputed`. Plus a cluster of write-set / two-writer problems (`cards/drafts/`, `BOARD.md`, hotfix vs `state.json`, monotonicity baseline) that are mechanical to fix. Twelve calls change the shape and go to the owner (section 1); the rest is fill work (section 2).

## 2. Accepted findings — fill worklist (no owner ruling needed; they are mechanics of things already decided)

**Hash contract**
- F1 (D1, C12) `§5` becomes the single normative gated-set enumeration, generated from the class column; reconcile the stale spots (F→L in §2.1/§7; `refs` "open" vs ruled; `traces` in §3 vs §4.1; epic `acceptance` in §3; guidance example ids).
- F2 (D1, D15c, C15) Scalar canonicalization table: datetimes → RFC 3339 UTC, offset required in gated fields; floats shortest-repr, `nan`/`inf` rejected; `ensure_ascii=false`, compact separators; arrays hash as written unless declared set-valued (`depends_on`, `surfaces`, `tags` — sorted, duplicates rejected); "prose" = exactly the `## Scope` text; pin `unicodedata.unidata_version` in `toolkit.lock`; a **conformance fixture corpus** both hashers must pass becomes a T-C2 matching condition.
- F3 (D2) Record `ext_schema_hash` (or config hash) in the fingerprint record; drift reason `ext-schema-changed`; ingest re-hashes all cards on an extension-schema commit.
- F4 (D3, C3) Ingest emits a typed `closure-invalidated` event for a gated edit that hits an un-landed closure (T-A13's refusal cannot fire when there is no explicit reopen); validator's implicit-reopen check states what it does when the snapshot is absent or older than the card's last qualifying commit.

**Layout / write sets / two writers**
- F5 (C6, D9) `BOARD.md` is a pure function of (cards, `state.json`, config) — never the live ledger; hook and lander run the *same* renderer; conflict rule "regenerate, never hand-merge" (post-merge regeneration; `merge=ours`); the lander updates `state.json` first, then renders. 1.3's "two disjoint write sets" corrected to name `BOARD.md` as generated-by-both.
- F6 (B12) Hotfix lane never writes `state.json`; its outcome lands with the next batch.
- F7 (C9, D6) Monotonicity is asserted against the ledger's last-landed projection (its cursor), not the working-tree file — a hand-edited sidecar is `state-divergent` and simply overwritten; every list entry gets a stable id (`closure_id`, `demotion_id`, `question_id`, `run_id`); add an execution status for a story reverted at batch review (else its closure still binds to the current hash and projects `closed`).
- F8 (C10, D7) Card files are never deleted (drafts abandon via `withdrawn`); validator rule `id.unique`; CI runs `cards check` on the merge result (pre-commit does not run on merges); deterministic repair on a duplicate: later commit loses, `renumbered_from` breadcrumb.
- F9 (C11, D8, B5) `log` append-only enforced over the parsed, newline-normalized model, keyed by card id not path; factory-side at ingest (`log.rewritten` = typed event, not "no event") and in PR CI against the merge-base; the newest block may be amended same-day (sartor's real practice — 0084's in-progress block was rewritten three times), older blocks hard.
- F10 (C17) `## Updates` citation anchor = ordinal `#u<n>`, date kept as text.

**Payload / builder-facing**
- F11 (D10, B13) Guidance-id coverage stated as a presence check of the same strength as scenario traceability; a `constraint` may carry an optional `check` in the scenario dialect that the close gate runs; `id` is an explicit key.
- F12 (D4) Run record carries `payload_hash`, `config_hash`, `refs_resolved = [{path, blob_sha}]`; `tags` forbidden as an input to any readiness/plan rule.
- F13 (D13) Efficiency stated honestly: id uniqueness, acyclicity, ladder, board need the full set — O(N) per commit/pick, sub-second to 500 cards; O(delta) via a blob-sha → (model, hash) cache (exact); ingest = one `git log --name-status` over the cursor range.

**Lifecycle / states**
- F14 (C4, D15e) Projected-status table rewritten: one row per label; order `state-divergent` / `unratified` › `withdrawn` › verified `closed` › readiness flags › execution status › `ratified`; epic roll-up rule (vacuous with zero children → `ratified`); withdrawn-in-flight mirrors demotion (`complete-but-withdrawn`); human `closed` on an already factory-closed card = no-op note.
- F15 (C-missing) Legal `status` transition table (who / when; `closed`→`withdrawn`? `withdrawn`→anything = no); the reopen path for a *human*-closed card; **re-dispatch of a failed card with no gated change** (T-A4 rule 5 requires re-ratification, but under (b) there is no no-op qualifying commit) — proposal: an owner ack via the factory CLI written to the ledger, same channel as `environment` answers.
- F16 (C-missing, D15d) Profiles for `sprint` and `milestone`; open-sprint selection; sprint-card ↔ batch binding when ratified mid-batch.

**Brownfield / ergonomics**
- F17 (B7) Migration synthesizes `source = "migrated"`, `captured_at` from the first Updates block, `template` default; WIP ceiling → config keys the schema references; drafts sectioned by `hold` / `tags`.
- F18 (B11, C13) Extension schema: classes G or T only (T only for prioritization/board-consumed fields, declared so); log-class extensions = lists (append) or set-once scalars; `required_when = "reopen" | "closed" | …` transition conditions (sartor's `x.guardrail` needs it).

## 4. What the refuters verified and could not break

Owner status vocabulary; TOML head; single `state.json` layout meets the history condition as written (append-only lists, git-delta-friendly, < 1 MB at 500 cards × 3 runs); ids option 1 removes the bot/owner race; per-scenario ids keep verdicts stable; hash-over-parsed-model neutralizes TOML representation variants, key order, comments, CRLF, slug renames; hand-edited `state.json` cannot forge state; toolkit tampering cannot forge the lock; human-only ratifier lists exclude bot identities by construction; fail-closed holds under canon/schema bumps, duplicate ids, unreadable ledger; `depends_on` gated + readiness-blocking is a sensible tightening; neither brownfield uses `[x]` so typing it costs nothing; sartor's own history (0030, 0019) shows reopen-keeps-id and closure-binds-to-evidence are real needs; draft tier stays cheap if the synthesized defaults exist; the memory tier's schema obligation (anchor + sha) is already met by the shape.
